# MCP gateway on GKE

An AI agent should not call every MCP server directly. This repo puts **one gateway** in front of them:
the agent talks to the gateway, the gateway authenticates the caller, decides which *tools* that caller may
see or call, and forwards to the right MCP server. Runs on GKE Autopilot with
[agentgateway](https://agentgateway.dev) 1.6 (Gateway API, MCP spec 2026-07-28).

> ## Status: working spike, not the finished platform
> What is deployed and tested today is the **core mechanism** with two toy servers. The enterprise parts
> (real IdP, three real servers, agent, network policy, observability) are planned, not built. See
> [Roadmap](#roadmap). Everything in the evidence below is captured output from a real run.

## What works today (checked by `./scripts/test.sh`)

| Claim | How it is proven |
|---|---|
| No token, garbage token, expired token, wrong audience, token from an untrusted key: all **HTTP 401** | 5 live checks |
| One endpoint federates two MCP servers (`tools/list` merges both) | viewer and operator list checks |
| A `viewer` token sees and can call **only read tools**; write tools are hidden and a direct call is refused | 6 live checks |
| An `operator` token sees all tools and can write | 2 live checks (13 in total) |
| Servers are stateless: no session affinity, any replica can answer (MCP 2026-07-28) | servers run `stateless_http=True` |

## Run it

```bash
gcloud config set project <your-project>     # billing linked
./scripts/up.sh      # ~12 min: Autopilot cluster, agentgateway, 2 servers, JWT + RBAC policy
./scripts/test.sh    # 13 live checks through the gateway; non-zero exit if any fail
./scripts/down.sh    # delete everything and prove nothing billable is left
```

**New to MCP gateways? Start with [docs/how-mcp-works.md](docs/how-mcp-works.md)** (components, request flow, OAuth/JWT, one vs many gateways, best practices).
Poke it by hand: [docs/runbook.md](docs/runbook.md). Design notes: [docs/architecture.md](docs/architecture.md).
Raw findings from the first spike: [spike/FINDINGS.md](spike/FINDINGS.md).

**Cost:** the GKE free tier credit covers the management fee for one Autopilot cluster; you pay for the pod
CPU/memory requested (about 5 small pods) and one load balancer. Leave it up for an hour, not a month.
`down.sh` removes everything.

## Known gaps

* The signing key is a throwaway generated by `up.sh` (stored in `.spike/`, gitignored). It is not an identity provider.
* The toy servers install their dependencies at start-up from PyPI; the real build uses signed images from Artifact Registry.
* **The gateway's Service is a public `LoadBalancer` on plain HTTP (port 80).** Every request still needs a valid JWT,
  but there is no TLS and no Cloud Armor. Fine for a spike you tear down; the real build puts TLS and an allow-list in front.
* The cluster API is reachable from your public IP only (`authorized_cidr`); if your IP changes, re-run `up.sh`.
