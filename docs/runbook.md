# Runbook

## Prerequisites
`gcloud` (logged in, project with billing), `terraform` >= 1.9, `kubectl`, `helm` >= 3.12, `python3`,
`gke-gcloud-auth-plugin` (`gcloud components install gke-gcloud-auth-plugin`).

## Bring it up / down
```bash
./scripts/up.sh --plan   # show what Terraform would create, change nothing
./scripts/up.sh          # build everything (~12 min). Safe to re-run.
./scripts/down.sh        # delete everything; prints clusters/forwarding-rules/addresses = 0 0 0
```
`up.sh` installs Keycloak first, waits for it, and only then applies the gateway policies (the gateway fetches the IdP's signing keys when the policy appears).

## Test
```bash
./scripts/test.sh        # 23 checks: discovery -> token -> gateway authN -> per-tool authZ. Every denial has a positive control.
```

## Try it yourself
```bash
./scripts/pf.sh          # terminal 1: gateway on localhost:18080, Keycloak on localhost:18081 (leave running)
# terminal 2:
.venv/bin/python tests/cli.py token agent-viewer                                      # decoded JWT: iss, aud, roles
.venv/bin/python tests/cli.py list agent-viewer                                       # 2 read tools
.venv/bin/python tests/cli.py list agent-operator                                     # 4 tools (same gateway URL)
.venv/bin/python tests/cli.py call agent-viewer mcp-alpha-8000_read_thing key=hello   # works
.venv/bin/python tests/cli.py call agent-viewer mcp-alpha-8000_write_thing key=a value=b   # refused: Unknown tool
.venv/bin/python tests/cli.py call agent-operator mcp-alpha-8000_write_thing key=a value=b  # works
.venv/bin/python tests/cli.py list agent-noaud    # HTTP 401: valid Keycloak token, but not addressed to this gateway
.venv/bin/python tests/cli.py list agent-norole   # HTTP 403: right audience, no role
curl -s localhost:18080/.well-known/oauth-protected-resource/mcp                      # discovery document
```
The four clients (`agent-viewer`, `agent-operator`, `agent-norole`, `agent-noaud`) and their secrets are generated by
`up.sh` into `.secrets/` (gitignored). Roles live in the Keycloak realm (`deploy/chart/files/realm.json.tpl`).

## Look inside the cluster
```bash
gcloud container clusters get-credentials mcp-gw-eu --region europe-west1
kubectl get pods -n mcp-platform -n agentgateway-system
kubectl -n mcp-platform get gateway,httproute,agentgatewaybackend,agentgatewaypolicy
kubectl -n mcp-platform logs deploy/mcp-gateway --tail=20                  # one line per request: status, caller
kubectl -n mcp-platform get agentgatewaypolicy tool-rbac -o yaml           # the per-tool RBAC rule (CEL)
kubectl -n agentgateway-system logs deploy/agentgateway | grep jwks        # the controller fetching Keycloak's keys
```

## Change who may call what
* **Roles / clients:** edit `deploy/chart/files/realm.json.tpl` and `values.yaml`, then `helm upgrade`. Keycloak imports the realm only at first start of an empty database, so also restart Keycloak (and see the key-cache note below).
* **Tool rules:** edit the CEL in `deploy/chart/templates/policies.yaml` (claims: `jwt.roles`, tool: `mcp.tool.name`), then re-run `./scripts/up.sh`. Anything not matched by an Allow rule is denied.

## Troubleshooting
| Symptom | Cause / fix |
|---|---|
| `kubectl` says `gke-gcloud-auth-plugin not found` | The plugin is in the gcloud SDK bin dir, not on PATH. The scripts add it; for your shell: `export PATH="$(gcloud info --format='value(installation.sdk_root)')/bin:$PATH"` |
| `kubectl` times out after your IP changed | The API allows only the IP used at `up.sh` time. Re-run `./scripts/up.sh`. |
| Server pods not Ready for ~1 min | They `pip install` the MCP SDK at start. Normal. |
| `curl` JSON-RPC to `/mcp` returns 400 with an empty body | MCP 2026-07-28 request shape differs from the old one. Use `tests/cli.py` / the SDK client. |
| Valid tokens suddenly get 401 (`token uses the unknown key` in the gateway log) | Keycloak restarted, so its signing keys changed (dev mode, in-memory DB). The controller caches the old key set for 5 min. Force a refetch: `kubectl -n mcp-platform delete agentgatewaypolicy mcp-authn && ./scripts/up.sh`. |
| Keycloak pod Ready but realm missing | The realm is imported only when the database is empty at start; after a dev-mode restart it re-imports from the Secret. Check `kubectl -n mcp-platform logs deploy/keycloak`. |
| You changed a policy and nothing changed | `kubectl -n mcp-platform get agentgatewaypolicy`: both columns must be `True`. |
| A denied tool returns "Unknown tool", not 403 | By design: the gateway hides tools the caller may not use. In the gateway log it shows as `http.status=400`. No token / bad token: 401. Valid token without a role: 403. |

## Cost check
`gcloud container clusters list`, `gcloud compute forwarding-rules list`, `gcloud compute addresses list`
should all be empty after `down.sh`.
